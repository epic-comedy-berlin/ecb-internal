Three things to know about Claude

Read this once before you start. It saves you confusion later.

¹
Claude doesn't run in the background

It's not a bot. It doesn't check Slack, send reminders, or update files on its own. Everything happens when someone opens a chat and prompts it.

²
Each chat is independent

What you say in chat A doesn't appear in chat B. So if you start a new chat with a question, Claude doesn't automatically know what you said in last week's chat.

That said: chats persist if you go back to them — close a chat and reopen it later, your conversation is still there. And Claude can search your past chats if you ask it to. So nothing's lost — it just isn't loaded automatically.

What IS loaded automatically: the three project files Aaron maintains (covered in the next section). Every fresh chat in the ECB project reads them at the start. That's why "fresh chats matter" — they always reflect the latest version of those files.

³
Claude can be wrong — push back

Sometimes Claude states something specific that contradicts what you know. It might invent a fact, misremember a previous decision, or recommend something that goes against ECB strategy. Don't accept it just because it sounds confident. You know ECB better than the chat does.

What Claude reads to know about ECB

When you start a fresh chat in the ECB Company Work project, Claude automatically loads three living files Aaron maintains. These are Claude's "memory" of ECB:

Active State
The current task list. Open tasks, who owns them, current statuses, active risks, pending decisions, next meetings. This is what your briefing comes from. Kept current by the log update after every meeting.
Master Context
The slow-moving facts about ECB — shows, team, brand, venues, infrastructure, strategic principles. The "what ECB is" file. Updated only on big shifts, via the Master Context update.
Decision Archive
Append-only history. Every decision made, meeting summary, document correction. The "why we got here" file. Read by Claude only when historical context is needed.

If something in your briefing looks out of date, the file is out of date. Tell Aaron in #p0-tasks and he'll fix it.

How Claude responds

Claude leads with the answer. For any substantive response — a recommendation, an analysis, a decision call — the first sentence or short paragraph contains the bottom line: what you need to know if you read nothing else. Reasoning, caveats, and detail follow underneath. If you're skimming, the top is enough.

Claude also defaults to the laziest viable approach that still answers the question. Smaller test budgets, fewer cells, shorter timeframes, simpler tools. Only scaling up when the small version proves the point. So if you ask for a plan, expect the minimum-viable version first, not a maximum-rigorous one.

If a response is too long or buries the answer

Push back. Useful one-liners: "Lead with the bottom line" · "Just the verdict, please" · "Cut it down — what's the actual recommendation?"

Claude will trim and re-front-load. You don't have to read paragraphs to find the point.

The models

Claude comes in three tiers — a fast one, an everyday one, and a heavy one. The version numbers below are the current line-up and will change as Anthropic releases new ones, but the roles stay the same: there's always a default daily driver, a deeper one for hard work, and a quick one for simple lookups. Default is the everyday tier — Sonnet 4.6 today. Claude tells you when to switch as part of any task it gives you, so you don't have to track the names yourself.

Sonnet 4.6
Default · Daily driver

For almost everything. Briefings, writing, drafts, social, email, research. Start here.

Opus 4.8
Heavy lifting

For deep work — contract review, complex strategy, long document analysis, anything that needs sustained reasoning.

Haiku 4.5
Fast & simple

For quick lookups or simple questions. Rarely the right pick for ECB work.

How tokens work — and why it matters for our shared account

Every message you send and every response Claude gives uses tokens (think of tokens as small chunks of text — roughly ¾ of a word each). Our Max plan has a token budget that resets every five hours. The whole team shares one account, so if one person burns through the limit on the wrong model, everyone is locked out until the reset.

The three models don't cost the same per token. Approximate ratios:

Haiku 4.5
1×
Cheapest per token
Sonnet 4.6
~3×
Three times Haiku's cost
Opus 4.8
~5×
Five times Haiku's cost — and Opus tends to "think" longer too

So an Opus chat doesn't just cost ~5× per token — Opus also generates more "thinking" tokens internally for deep reasoning. In practice a long Opus session can chew through 10× what the same conversation on Sonnet would cost. Use Opus when the task genuinely needs it. Default to Sonnet for everything else.

What burns tokens fastest

Long chats. Every new message re-processes the entire chat history. A 30-message chat costs more per turn than a 5-message one. Start a fresh chat for each new task.

Wrong model for the job. Running simple admin on Opus burns 5× the tokens for zero quality gain.

Pasting whole documents repeatedly. A PDF or long doc gets re-read with every message until you start a new chat.

How to switch models

Look at the bottom of the chat input box (where you type). You'll see the current model name (e.g. "Claude Sonnet 4.6") with a small dropdown arrow next to it. Click the model name, pick the model you want from the dropdown, then send your next message. The change applies from your next message onwards — your conversation history is preserved.

Should you switch models mid-chat?

Usually no. For most ECB work, pick one model and stay there.

Switching mid-chat is possible — your conversation carries over — but it isn't free: the new model re-reads the whole chat history before responding, billed at its rate. So switching frequently is wasteful. The honest rule: default to Sonnet 4.6 and stay there. The one time a switch earns its cost is when Claude told you to start on Opus for genuine deep thinking and that phase is clearly over with real execution work still ahead — then drop back to Sonnet, once.

The one-line rule

Default Sonnet 4.6 for the whole chat. The only time switching makes sense is when (a) Claude explicitly told you to start on Opus for genuine deep thinking, AND (b) the heavy thinking phase is clearly over and you've still got significant execution work ahead. Then drop back to Sonnet, once. Otherwise, stay where you are.

Coordinating with the team

Because we share one Max plan, your model choices and chat habits affect everyone. A few simple rules keep the team unblocked.

Channel discipline — read this first

#p0-tasks is for tasks ONLY. Task completion handoffs, status updates on specific tasks, task-related questions. Nothing else.

Everything else goes in #p1-important. Heads-up posts, dependency flags, coordination, decisions, things people need to know but that aren't tasks themselves. All the slack examples below go in #p1-important — not #p0-tasks.

Full channel map and how Slack works at ECB: the Slack guide.

If you have a time-sensitive task that blocks others

Post in #p1-important before you start. Format:

#p1-important
Heads up — I'm starting a heavy contract review now (Opus, probably 1–2 hours of heavy use). Brendan needs the output by Thursday morning. If you're planning anything heavy in the next few hours, let me know so we can sequence it.

This isn't about asking permission — it's about making sure the rest of the team knows the limit might be tight, so nobody else fires off a low-urgency Opus session and locks the whole account out for five hours.

If someone else has flagged a heavy task

Hold off on your own non-urgent heavy work until they're done. Sonnet stuff is usually fine — the limit handles parallel Sonnet work much better than parallel Opus work. The thing to avoid is two people running simultaneous Opus sessions on time-sensitive deliverables.

After meetings — flag what needs doing and when

If a meeting produces work that someone else is blocked on, post the dependency clearly in #p1-important:

#p1-important
From today's meeting — I need the venue research finished by Wednesday so Ori can pitch on Thursday. Ori, this is on you. Flag if you can't hit Wednesday and we'll re-plan.
#p1-important
Reminder: my contract review is the blocker for Brendan's Thursday call. Aiming to finish by Wednesday EOD. Will post here when done.

The rule: if your work blocks someone else's, name the dependency explicitly. Don't assume people remember from the meeting. The chain only moves if everyone knows where they are in it.

If the limit hits

Claude tells you when the next reset window opens (usually 5 hours from when you hit the cap). Post in #p1-important immediately so nobody else tries to use the account in that window. Plan around the reset — non-urgent stuff can wait, time-sensitive work moves to the front of the queue once the cap clears.

Doing work outside the task system

Sometimes you want to do something that isn't on your task list — brainstorm an idea, ask a one-off question, draft something quick, think through a creative thought. The task-briefing flow doesn't fit. Here's the alternative.

Lyra is a prompt specialist — a saved chat in your sidebar called LYRA that turns rough requests into precision-crafted prompts. It's the same Lyra you use for complex tasks in the Task Guide, but for off-list work you skip the briefing chat entirely and go straight to it.

When to use this path

Use case 1 — Brainstorming

You want to think through an idea that isn't a current task. "Help me come up with show titles for a Tuesday improv format" or "What angles could we try for a Wise Fools episode about free will?"

Use case 2 — Quick ad-hoc question

You have a one-off question that doesn't fit "pick a P1/P2 task." "What's the best time of day to post on TikTok for our audience?" or "Help me write a polite reply to a comedian asking for stage time."

Use case 3 — Drafting something off-list

You need a tweet, an Instagram caption, a quick email, a creative pitch — anything not on the formal task list. "Draft 5 versions of an Instagram caption for the bit about Brendan misreading 'Ausgang'."

The process

1

Decide what you want to do

Be rough about it. You don't need to clean it up — that's what Lyra is for.

2

Open the LYRA chat

Find LYRA in the Starred section of the sidebar. Click it.

3

Type BASIC or DETAIL + your request

Start with the trigger word, then describe what you want in plain language.

BASIC — quick optimisation. Use for everyday off-list stuff. Lyra returns a polished prompt right away.

DETAIL — for high-stakes work where the framing matters. Lyra builds a more comprehensive, carefully-scoped prompt. It will ask clarifying questions only if it needs missing context — most of the time it just returns the optimised prompt straight away.

Example — BASIC request
BASIC using Claude — give me 5 angles for a TikTok caption about a comedian who can't read German signs. ECB tone — punchy, not corporate.
Example — DETAIL request
DETAIL using Claude — help me think through whether ECB should pitch a corporate comedy package to the Berlin tech sector. We've had requests but no formal offering yet.
4

Copy the optimised prompt

Lyra outputs a "Your Optimized Prompt:" block. Copy the whole thing.

5

Open a NEW chat in ECB Company Work

Important — this is different from the task flow. Don't use a briefing chat (those are task-specific). Go to ECB Company Work in the Starred section of your sidebar and start a fresh chat.

6

Switch the model if needed

Most off-list work runs fine on Sonnet 4.6. If you're doing something complex (deep strategic thinking, long-form writing, contract-style analysis), switch to Opus 4.8: click the model name at the bottom of the chat input box, pick the model from the dropdown.

7

Paste and send

Paste the optimised prompt. Hit enter. Claude takes it from there — same guided behaviour as a normal task.

If anything useful comes out of it

There's no Slack handoff for off-list work since it isn't in the task system. But if something comes out of your chat that should become a real task, decision, or strategy direction, post it in #p0-tasks or #p1-important so Aaron can capture it. Otherwise it disappears with the chat.

The other chats in the sidebar

You'll see a few other items in the Starred section. The one you'll use is LYRA; the rest are Aaron's, and you don't need to touch them. Here's what each one is so you know what's what.

LYRA
You'll use this. The prompt specialist — turns rough requests into precision-crafted prompts. Used in the task workflow (Step 5) and for off-list work. Also handy for any deeper research task — set up the prompt in LYRA, then run the optimised version in a fresh ECB Company Work chat.
MA / MIR / LOG
Aaron's older working chats — don't post in them. Note: meeting agendas, MIRs, and log updates are no longer run from these dedicated chats. Each now runs in a fresh chat inside ECB Company Work, triggered by a phrase. See the Meeting Agendas, MIR, and Log Update guides for how each one works now.

If something looks wrong

If your briefing seems off

You completed a task but it's still showing as open. Or a task is missing. Or a status looks stale.

What to do: Post in #p0-tasks with the correction. Aaron updates the task file. Your next fresh briefing reflects the fix.

Don't try to maintain the system yourself. The chat is for doing work — Aaron handles file maintenance.

If Claude says something that doesn't match what you know

Claude can be wrong mid-task. It might invent a fact, misremember a previous decision, or recommend something that contradicts known ECB strategy.

Push back. Tell Claude: "That doesn't sound right — verify it" or "That contradicts X, please correct." Don't just accept what it says because it sounds confident.

If the optimised prompt from Lyra feels off

Lyra is good but not infallible. If the optimised prompt seems to miss the point of what you wanted, paste it back into Lyra with a note like "This is missing X — try again." Better to iterate than run a prompt that won't deliver.

Always make Claude check its own work

For anything important — a draft going out, a decision recommendation, a plan, a contract analysis, a final deliverable — explicitly ask Claude to verify before you use it.

Useful prompts: "Check your work — list every requirement I gave you and confirm each one is covered" or "Verify the facts in this draft against the project files" or "Is anything in this output unsupported or guessed?"

Claude will often catch its own errors when asked to look. It just doesn't always do it on its own. Two minutes of self-check saves an hour of fixing something later.

Questions?

Ask Aaron in #p1-important or #p2-general. If you get stuck mid-task, you can also just ask Claude — it knows the system.
